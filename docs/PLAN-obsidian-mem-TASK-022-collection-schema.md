## Prior art + risk spike (from RESEARCH-FINDINGS.md)

- The chunk_text `enable_analyzer` + BM25 Function → auto SparseFloatVector pattern is
  PROVEN on milvus-lite by memsearch (`/home/derek/src/memsearch/src/**/store.py:148-179`):
  content VARCHAR(65535) enable_analyzer + SPARSE_FLOAT_VECTOR auto-generated by BM25
  Function(content). Mirror it (index type COSINE/FLAT or IP for dense there; pick and pin).
- NOVELTY RESOLVED BY VERIFICATION (milvus-transformers-findings §3, 49/49 + 34/34 on
  lite 3.2.2 + SDK 3.0.6): partition key (`is_partition_key` + `num_partitions: 16`) with
  dynamic values WORKS; `Array<VarChar>` (element_type/max_capacity/max_length) +
  `ARRAY_CONTAINS`/`ARRAY_CONTAINSAny`/`ARRAY_LENGTH` WORK; TEXT_MATCH works with
  `enable_analyzer` alone; `hybridSearch` dense+BM25 with RRFRanker/WeightedRanker WORKS.
  Keep scripts/spike-milvus.mjs as a boot smoke (re-run on milvus-lite version bumps)
  rather than a gate; fallbacks stay documented (scope→plain scalar filter, arrays→comma
  CSV + LIKE) if a future lite release regresses.
